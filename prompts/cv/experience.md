# Professional Experience Specification

## Objetivo

Definir las reglas para construir la sección **Professional Experience** del currículum.

Esta sección representa la mayor parte del valor del CV y debe demostrar, mediante evidencia, la capacidad profesional del candidato.

---

# Propósito

Cada experiencia debe responder una única pregunta:

> ¿Qué evidencia demuestra que el candidato puede desempeñar exitosamente el puesto al que está aplicando?

Nunca describir únicamente responsabilidades.

Siempre demostrar impacto.

---

# Ubicación

La sección deberá aparecer inmediatamente después de **Core Competencies**.

Nunca modificar esta posición.

---

# Fuente de información

Toda la información deberá provenir exclusivamente de la Career Knowledge Base.

Nunca inventar:

- responsabilidades
- proyectos
- tecnologías
- métricas
- logros
- resultados
- fechas
- cargos

Si una información no existe en la KB deberá omitirse.

---

# Selección de experiencias

No todas las experiencias tienen el mismo peso.

Antes de construir el CV, clasificar cada experiencia según su relevancia para la vacante.

Prioridad:

Alta

Media

Baja

Las experiencias con prioridad alta deberán ocupar mayor espacio.

Las experiencias con prioridad baja deberán resumirse.

Nunca eliminar experiencias importantes únicamente para reducir longitud.

---

# Orden

Mostrar siempre las experiencias en orden cronológico inverso.

La experiencia más reciente deberá aparecer primero.

---

# Estructura obligatoria

Cada experiencia deberá contener exactamente el siguiente orden.

Empresa

Cargo

Periodo

Tecnologías principales

Bullets

No alterar este orden.

---

# Empresa

Mostrar únicamente el nombre oficial de la empresa documentado en la KB.

No agregar descripciones.

---

# Cargo

Utilizar el cargo oficial documentado en la KB.

Cuando el CV se genere en otro idioma, adaptar la traducción sin modificar el nivel real del puesto.

Nunca incrementar el seniority.

---

# Fechas

Mantener un único formato en todo el documento.

Ejemplo:

May 2025 – Present

Nunca mezclar formatos.

---

# Tecnologías

Cada experiencia deberá contener una línea exclusiva para las tecnologías más relevantes.

Mostrar únicamente tecnologías utilizadas de manera significativa.

No convertir esta línea en una lista exhaustiva.

Objetivo:

Entre 4 y 8 tecnologías.

Formato:

SQL Server | PostgreSQL | C# | REST APIs | Git

Nunca utilizar listas verticales.

---

# Bullets

Cada experiencia deberá contener entre:

3 y 6 bullets.

No utilizar menos de tres.

No utilizar más de seis.

---

# Priorización de bullets

Los bullets deberán ordenarse por impacto.

El primer bullet siempre deberá representar la contribución más relevante para la vacante.

No ordenar cronológicamente.

Ordenar estratégicamente.

---

# Objetivo de cada bullet

Cada bullet deberá comunicar al menos uno de los siguientes aspectos:

- problema resuelto
- mejora implementada
- automatización
- optimización
- liderazgo
- reducción de riesgo
- ahorro
- escalabilidad
- calidad
- disponibilidad
- satisfacción del cliente

---

# Longitud

Objetivo:

Una línea.

Máximo:

Dos líneas.

Nunca convertir un bullet en un párrafo.

---

# Contenido

Cada bullet deberá describir únicamente una idea.

Nunca combinar múltiples logros independientes.

---

# Estructura recomendada

Siempre que exista evidencia suficiente, construir cada bullet utilizando la siguiente lógica.

Acción

↓

Contexto

↓

Resultado

↓

Impacto

No todos los elementos son obligatorios.

Pero siempre deberá existir una consecuencia observable.

---

# Tecnologías dentro de bullets

Mencionar tecnologías únicamente cuando aporten contexto.

No repetir tecnologías que ya aparecen en la línea de tecnologías.

---

# Responsabilidades

No listar tareas diarias.

Priorizar contribuciones.

Un bullet que describa únicamente una responsabilidad sin demostrar impacto deberá eliminarse.

---

# Logros

Los logros deberán integrarse dentro de los bullets.

Nunca crear una subsección de logros.

---

# Métricas

Cuando existan métricas documentadas en la KB deberán utilizarse.

Nunca inventarlas.

Nunca estimarlas.

Nunca modificarlas.

---

# Adaptación

Cada vacante deberá generar una versión diferente de esta sección.

La adaptación puede modificar:

- orden de bullets
- cantidad de bullets
- tecnologías mostradas
- experiencias priorizadas

Nunca modificar hechos.

---

# Experiencias poco relevantes

Cuando una experiencia tenga baja relación con la vacante:

Reducirla.

Nunca expandir experiencias poco relevantes únicamente para ocupar espacio.

---

# Experiencias altamente relevantes

Cuando una experiencia tenga alta relación con la vacante:

Expandirla.

Puede utilizar el máximo número permitido de bullets.

---

# Consistencia

Todas las experiencias deberán utilizar exactamente la misma estructura.

No permitir formatos diferentes entre empresas.

---

# Redundancia

Eliminar bullets que describan:

- la misma responsabilidad;
- la misma tecnología;
- el mismo proyecto;
- el mismo logro.

Cada bullet debe aportar información nueva.

---

# Evidencia

Toda afirmación deberá poder demostrarse mediante la KB.

Si no existe evidencia suficiente deberá eliminarse.

---

# Legibilidad

Un reclutador deberá poder identificar en menos de 20 segundos:

- responsabilidades principales;
- tecnologías utilizadas;
- impacto generado;
- nivel técnico;
- evolución profesional.

---

# Calidad

Antes de finalizar verificar que:

- todas las experiencias siguen la misma estructura;
- los bullets están ordenados por relevancia;
- no existen responsabilidades sin impacto;
- no existen tecnologías repetidas innecesariamente;
- no existen métricas inventadas;
- todas las afirmaciones tienen evidencia;
- la sección está adaptada específicamente a la vacante.

---

# Responsabilidad

Este documento únicamente define cómo construir la sección **Professional Experience**.

No define:

- estructura general del CV;
- Professional Summary;
- Projects;
- Skills;
- Education;
- Languages;
- reglas ATS;
- reglas generales de redacción.

Estas reglas se encuentran en los documentos especializados correspondientes.
