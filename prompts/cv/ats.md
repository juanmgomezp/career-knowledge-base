# ATS Specification

## Objetivo

Definir las reglas necesarias para maximizar la compatibilidad del currículum con Applicant Tracking Systems (ATS).

Este documento establece únicamente las reglas relacionadas con el procesamiento automático del CV.

No define contenido, estructura ni estilo de redacción.

---

# Principios

El CV debe ser fácilmente procesado tanto por sistemas ATS como por reclutadores humanos.

La prioridad siempre será:

1. Correcta interpretación del contenido.
2. Extracción precisa de información.
3. Facilidad de lectura.
4. Optimización para palabras clave.

Nunca sacrificar legibilidad por intentar mejorar el ATS.

---

# Compatibilidad

El documento debe ser compatible con los ATS modernos utilizados por empresas internacionales.

Incluyendo, entre otros:

- Workday
- Greenhouse
- Lever
- Ashby
- SmartRecruiters
- Taleo
- iCIMS
- BambooHR

No optimizar el CV para un ATS específico.

Optimizar para estándares generales.

---

# Formato del documento

El CV deberá entregarse como un archivo Microsoft Word (.docx).

No utilizar formatos propietarios.

No generar archivos protegidos.

El contenido debe permanecer completamente editable.

---

# Estructura

Utilizar únicamente encabezados estándar ampliamente reconocidos.

Encabezados permitidos:

- Professional Summary
- Core Competencies
- Professional Experience
- Selected Projects
- Technical Skills
- Education
- Languages

No inventar nombres de secciones.

No utilizar títulos creativos.

---

# Lectura automática

Todo el contenido debe poder leerse de arriba hacia abajo.

Nunca utilizar:

- múltiples columnas
- contenido flotante
- elementos laterales
- cuadros de texto
- tablas ocultas
- estructuras complejas

La lectura debe ser completamente lineal.

---

# Elementos prohibidos

Nunca utilizar:

- iconos
- imágenes
- logotipos
- gráficos
- emojis
- SmartArt
- WordArt
- formas
- barras de progreso
- estrellas de valoración
- gráficos de habilidades
- fondos de color
- marcas de agua

---

# Tipografía

Utilizar fuentes estándar.

Preferencia:

- Calibri
- Aptos
- Arial

Evitar fuentes decorativas.

Mantener consistencia tipográfica.

---

# Keywords

Antes de construir el CV:

Analizar la Job Description.

Extraer automáticamente:

- tecnologías
- herramientas
- plataformas
- metodologías
- responsabilidades
- competencias
- productos
- procesos

Integrar únicamente aquellas que tengan evidencia real dentro de la KB.

Nunca inventarlas.

---

# Integración de Keywords

Las palabras clave deben aparecer de forma natural.

Nunca agregarlas únicamente para aumentar coincidencias.

Cada keyword debe estar respaldada por:

- experiencia
- proyecto
- habilidad
- logro

---

# Keyword Stuffing

Está prohibido.

Nunca repetir tecnologías únicamente para incrementar coincidencias ATS.

Ejemplo incorrecto:

SQL Server | SQL | Microsoft SQL | T-SQL | SQL Database | MSSQL

Utilizar únicamente la denominación más apropiada.

---

# Tecnologías

Las tecnologías deben aparecer únicamente cuando exista experiencia demostrable.

Evitar incluir herramientas utilizadas únicamente de manera experimental.

La experiencia demostrada siempre tiene prioridad.

---

# Sinónimos

Cuando sea apropiado y exista evidencia suficiente, utilizar la terminología empleada por la vacante.

Ejemplo:

Si la vacante utiliza:

Customer Support

y la KB contiene:

Technical Support

Puede adaptarse la redacción siempre que el significado permanezca correcto.

Nunca cambiar el sentido de la experiencia.

---

# Acrónimos

La primera aparición puede incluir el nombre completo cuando sea conveniente.

Ejemplo:

Service Level Agreement (SLA)

Posteriormente utilizar únicamente:

SLA

Mantener consistencia.

---

# Fechas

Mantener un formato uniforme.

Ejemplo:

May 2025 – Present

Nunca mezclar formatos.

---

# Cargos

Utilizar el cargo más representativo documentado en la KB.

Cuando sea necesario para la vacante, adaptar la traducción.

Nunca modificar el nivel real del cargo.

Nunca aumentar seniority.

---

# Empresas

Mantener siempre:

Empresa

Cargo

Fechas

No invertir el orden.

---

# Experiencia

Priorizar experiencias relevantes.

Reducir experiencias con baja relación respecto a la vacante.

No eliminar experiencia significativa únicamente para reducir longitud.

---

# Proyectos

Incluir únicamente proyectos relevantes.

No utilizar proyectos como relleno.

Cada proyecto debe reforzar competencias solicitadas por la vacante.

---

# Skills

Mostrar únicamente habilidades demostradas.

Nunca incluir listas genéricas.

Cada habilidad debe tener respaldo dentro de la KB.

---

# Educación

Mantener únicamente información relevante.

Evitar información académica innecesaria cuando exista amplia experiencia profesional.

---

# Idiomas

Mostrar únicamente idiomas con nivel conocido.

Nunca estimar niveles.

Nunca utilizar términos ambiguos.

---

# Consistencia

Todo el documento debe mantener:

- mismo formato de fechas
- misma puntuación
- misma capitalización
- mismo estilo de encabezados
- misma estructura de bullets

---

# Duplicados

Eliminar información repetida entre:

- Summary
- Experience
- Projects
- Skills

Cada sección debe aportar información distinta.

---

# Escaneo

El CV debe permitir que un reclutador identifique en menos de 30 segundos:

- perfil profesional
- tecnologías principales
- experiencia relevante
- logros principales
- nivel profesional

---

# Longitud

La optimización ATS nunca debe aumentar innecesariamente la longitud del documento.

Objetivo:

1 página.

Máximo:

2 páginas.

---

# Validación ATS

Antes de finalizar verificar:

- no existen tablas;
- no existen columnas;
- no existen iconos;
- no existen imágenes;
- no existen cuadros de texto;
- los encabezados son estándar;
- todas las keywords tienen evidencia;
- no existe keyword stuffing;
- el contenido puede leerse linealmente;
- el documento mantiene consistencia visual.

---

# Responsabilidad

Este documento únicamente define las reglas relacionadas con ATS.

No define:

- estructura visual;
- redacción;
- selección de experiencias;
- contenido de cada sección;
- validaciones generales.

Estas reglas se encuentran en los documentos especializados correspondientes.
