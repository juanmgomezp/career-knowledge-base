# Selected Projects Specification

## Objetivo

Definir las reglas para construir la sección **Selected Projects** del currículum.

Esta sección tiene como propósito reforzar las competencias más relevantes para la vacante mediante proyectos documentados en la Career Knowledge Base.

No debe convertirse en un segundo historial laboral.

---

# Propósito

Cada proyecto debe responder una única pregunta:

> ¿Este proyecto aumenta significativamente la probabilidad de obtener una entrevista para esta vacante?

Si la respuesta es no, el proyecto no debe incluirse.

---

# Ubicación

La sección deberá aparecer inmediatamente después de **Professional Experience**.

Nunca modificar esta posición.

---

# Fuente de información

Todos los proyectos deberán obtenerse exclusivamente de la Career Knowledge Base.

Nunca inventar:

- proyectos
- tecnologías
- resultados
- objetivos
- métricas
- fechas
- responsabilidades

Si un proyecto no existe en la KB deberá omitirse.

---

# Selección

No incluir todos los proyectos.

Seleccionar únicamente aquellos que aporten valor directo para la vacante.

Cada proyecto debe reforzar una competencia importante solicitada por la empresa.

---

# Cantidad

Objetivo:

2 proyectos.

Máximo:

3 proyectos.

Nunca incluir más de tres.

Si ningún proyecto aporta valor, omitir completamente esta sección.

---

# Priorización

Ordenar los proyectos según su relevancia para la vacante.

Nunca por fecha.

Nunca por complejidad.

Nunca por preferencia personal.

---

# Información obligatoria

Cada proyecto deberá contener únicamente:

Nombre

Descripción

Tecnologías principales

No agregar información adicional.

---

# Nombre

Utilizar el nombre oficial documentado en la KB.

No modificarlo.

No crear nombres comerciales.

---

# Descripción

La descripción debe responder únicamente:

- qué problema resolvió;
- cuál fue la solución implementada;
- cuál fue el impacto.

No describir el proceso completo.

No narrar el proyecto.

No repetir información presente en Professional Experience.

---

# Longitud

Cada descripción deberá ocupar entre:

1 y 3 líneas.

Nunca convertir la descripción en un párrafo largo.

---

# Tecnologías

Mostrar únicamente las tecnologías principales.

Objetivo:

Entre 3 y 6 tecnologías.

Formato:

SQL Server | C# | REST APIs | Git

Nunca utilizar listas verticales.

---

# Adaptación

Cada vacante puede generar una combinación diferente de proyectos.

La selección dependerá únicamente de su relevancia.

---

# Relación con Experience

La sección Projects complementa la experiencia profesional.

Nunca sustituye una experiencia.

Nunca duplica un bullet existente.

Cada proyecto debe aportar información nueva.

---

# Tecnologías repetidas

Evitar repetir tecnologías innecesariamente.

Si una tecnología aparece en Experience y vuelve a aparecer en Projects deberá aportar contexto adicional.

---

# Métricas

Cuando existan métricas documentadas en la KB podrán utilizarse.

Nunca inventarlas.

Nunca estimarlas.

Nunca modificarlas.

---

# Proyectos personales

Incluir únicamente si:

- aportan valor para la vacante;
- están documentados en la KB;
- demuestran competencias relevantes.

No incluir proyectos únicamente por estar publicados en GitHub.

---

# GitHub

No agregar enlaces a GitHub salvo que:

- el proyecto sea público;
- el repositorio represente correctamente el trabajo realizado;
- aporte valor directo para la vacante.

Si el enlace no aporta valor, omitirlo.

---

# Redundancia

Eliminar proyectos que únicamente repitan:

- responsabilidades;
- tecnologías;
- resultados;
- experiencia profesional.

Cada proyecto debe reforzar una capacidad distinta.

---

# Legibilidad

El reclutador debe comprender cada proyecto en menos de 15 segundos.

Eliminar cualquier detalle innecesario.

---

# Calidad

Antes de finalizar verificar que:

- todos los proyectos provienen de la KB;
- todos los proyectos son relevantes para la vacante;
- no existen proyectos duplicados;
- no existen tecnologías inventadas;
- no existen resultados sin evidencia;
- la sección aporta información distinta a Experience.

---

# Omisión

Si ningún proyecto incrementa claramente el valor del CV para la vacante, eliminar completamente la sección.

Es preferible no mostrar proyectos que incluir proyectos irrelevantes.

---

# Responsabilidad

Este documento únicamente define cómo construir la sección **Selected Projects**.

No define:

- estructura general del CV;
- reglas de redacción;
- reglas ATS;
- Professional Summary;
- Professional Experience;
- Technical Skills;
- Education;
- Languages;
- validaciones generales.

Estas reglas se encuentran en los documentos especializados correspondientes.
