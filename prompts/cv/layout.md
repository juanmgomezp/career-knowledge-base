# CV Layout Specification

## Objetivo

Definir la estructura visual, organización, jerarquía y distribución del contenido del currículum.

Este documento no define reglas de redacción ni criterios de selección de información.

Únicamente especifica cómo debe organizarse el documento final.

---

# Principios

El CV debe priorizar:

- claridad
- legibilidad
- simplicidad
- profesionalismo
- compatibilidad ATS

Nunca debe priorizar elementos visuales sobre la lectura.

El diseño debe ser completamente funcional.

---

# Tipo de documento

Generar un documento Microsoft Word (.docx).

No utilizar plantillas gráficas.

No generar PDF.

No generar Markdown.

---

# Compatibilidad ATS

Todo el documento debe ser ATS Friendly.

Nunca utilizar:

- tablas
- columnas
- cuadros de texto
- imágenes
- iconos
- emojis
- SmartArt
- WordArt
- gráficos
- barras de progreso
- elementos flotantes
- encabezados decorativos

Todo el contenido debe estar organizado en una única columna.

---

# Tamaño

Objetivo:

1 página.

Permitido:

Hasta 2 páginas.

Nunca superar las 2 páginas.

---

# Márgenes

Utilizar márgenes estándar de Microsoft Word.

Evitar márgenes excesivamente pequeños para ganar espacio.

La legibilidad siempre tiene prioridad.

---

# Fuente

Utilizar una fuente profesional.

Preferencia:

- Calibri
- Aptos
- Arial

Tamaño recomendado:

Nombre:
16–18 pt

Encabezados:
12–14 pt

Contenido:
10–11 pt

Mantener consistencia en todo el documento.

---

# Espaciado

Mantener un espaciado compacto.

Evitar espacios innecesarios.

Separar únicamente las secciones principales.

No dejar líneas en blanco repetidas.

---

# Alineación

Todo el documento debe utilizar alineación izquierda.

No justificar texto.

No centrar secciones.

Únicamente el nombre puede aparecer centrado o alineado a la izquierda.

El resto del documento debe mantenerse alineado a la izquierda.

---

# Encabezado

El encabezado debe contener exactamente:

Nombre

Headline profesional

Información de contacto

Orden:

Nombre

Headline

Email | Teléfono | Ubicación | LinkedIn | GitHub

Toda la información de contacto debe mantenerse en una sola línea.

Utilizar "|" como separador.

Ejemplo:

correo@dominio.com | +52 xxx xxx xxxx | Mérida, México | LinkedIn | GitHub

Nunca dividir esta línea.

---

# Orden obligatorio de secciones

El documento deberá seguir exactamente el siguiente orden.

1. Professional Summary

2. Core Competencies

3. Professional Experience

4. Selected Projects

5. Technical Skills

6. Education

7. Languages

Nunca alterar este orden.

---

# Professional Summary

Debe aparecer inmediatamente después del encabezado.

Nunca exceder cuatro líneas.

No utilizar listas.

Siempre redactar en un único párrafo.

---

# Core Competencies

Mostrar inmediatamente después del Summary.

Presentar como una única línea horizontal.

Ejemplo:

Application Support | SQL Server | Root Cause Analysis | Incident Management | Process Improvement | SaaS | Customer Support

No utilizar bullets.

No utilizar columnas.

---

# Professional Experience

Cada experiencia debe seguir exactamente esta estructura.

Empresa

Cargo

Fechas

Tecnologías principales

Bullets

Orden:

Company Name

Position | Start Date – End Date

SQL Server | C# | REST APIs | Freshdesk

• Bullet

• Bullet

• Bullet

• Bullet

Separar experiencias mediante una única línea en blanco.

---

# Tecnologías por experiencia

Cada experiencia debe contener una línea exclusiva para las tecnologías utilizadas.

Las tecnologías deberán mostrarse horizontalmente.

Utilizar "|" como separador.

Ejemplo:

SQL Server | PostgreSQL | REST APIs | Git | Azure DevOps

Nunca utilizar listas verticales.

---

# Bullets

Todos los bullets deben mantener el mismo nivel de indentación.

No utilizar numeración.

No utilizar subniveles.

No utilizar párrafos largos.

---

# Selected Projects

Incluir únicamente proyectos relevantes para la vacante.

Cada proyecto deberá contener:

Nombre

Descripción breve

Tecnologías

Ejemplo:

SQL Operations Optimization System

Permission management and automation platform that eliminated recurring support processes and improved operational efficiency.

SQL Server | T-SQL | Stored Procedures

Separar proyectos mediante una única línea en blanco.

---

# Technical Skills

Organizar por categorías.

Mostrar únicamente categorías que contengan información.

Orden recomendado:

Databases

Programming

Frameworks

Cloud

Tools

Methodologies

Cada categoría debe mostrarse en una única línea.

Ejemplo:

Databases

SQL Server | PostgreSQL | MongoDB

Programming

C# | JavaScript | Python

Nunca utilizar listas verticales.

---

# Education

Orden:

Título

Institución

Año

Ejemplo:

Bachelor's Degree in Computer Systems Engineering

Instituto Tecnológico Superior de Valladolid

2014

Cada formación deberá separarse mediante una línea en blanco.

---

# Languages

Mostrar únicamente idioma y nivel.

Ejemplo:

Spanish — Native

English — Upper-Intermediate (B2)

No agregar descripciones.

---

# Longitud por sección

Professional Summary

3–4 líneas.

Core Competencies

1 línea.

Professional Experience

70–75 % del documento.

Selected Projects

10–15 % del documento.

Technical Skills

10 % del documento.

Education

5 % del documento.

Languages

2–3 líneas.

---

# Densidad del contenido

Cada línea del documento debe aportar información relevante.

Eliminar:

- líneas vacías innecesarias
- encabezados repetidos
- texto decorativo
- explicaciones
- contenido redundante

---

# Consistencia

Todos los encabezados deben utilizar exactamente el mismo formato.

Todos los bullets deben utilizar el mismo símbolo.

Todas las fechas deben utilizar el mismo formato.

Todos los separadores deben utilizar el carácter "|".

Toda la jerarquía visual debe mantenerse consistente.

---

# Adaptabilidad

La estructura nunca cambia.

Lo único que cambia entre una vacante y otra es:

- contenido
- experiencias seleccionadas
- proyectos seleccionados
- tecnologías mostradas
- competencias mostradas

El diseño permanece idéntico para todas las vacantes.

---

# Responsabilidad

Este documento únicamente define la estructura del CV.

No define:

- cómo redactar el Summary;
- cómo escribir los bullets;
- cómo seleccionar experiencias;
- cómo optimizar ATS;
- cómo validar el resultado.

Estas reglas se encuentran en los documentos especializados correspondientes.
