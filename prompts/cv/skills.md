# Technical Skills Specification

## Objetivo

Definir las reglas para construir la sección **Technical Skills** del currículum.

Esta sección debe proporcionar una visión rápida y organizada de las competencias técnicas del candidato, basándose exclusivamente en habilidades demostradas dentro de la Career Knowledge Base.

No debe convertirse en un inventario exhaustivo de tecnologías.

---

# Propósito

La sección debe responder una única pregunta:

> ¿Cuáles son las principales competencias técnicas del candidato relevantes para esta vacante?

Debe permitir al reclutador identificar rápidamente las capacidades técnicas más importantes.

---

# Ubicación

La sección deberá aparecer después de **Selected Projects**.

Si la sección Projects se omite, Technical Skills deberá aparecer inmediatamente después de Professional Experience.

Nunca modificar esta posición.

---

# Fuente de información

Toda habilidad técnica deberá estar respaldada por evidencia documentada dentro de la Career Knowledge Base.

Nunca agregar:

- tecnologías no utilizadas;
- herramientas aprendidas únicamente mediante cursos;
- software utilizado de forma superficial;
- habilidades inferidas;
- conocimientos asumidos.

Si no existe evidencia suficiente, la habilidad deberá omitirse.

---

# Función

Technical Skills resume.

No demuestra.

La evidencia pertenece a:

- Professional Experience
- Selected Projects

---

# Organización

Las habilidades deberán agruparse por categorías.

Las categorías deberán facilitar la lectura.

---

# Categorías recomendadas

Las categorías podrán incluir, cuando exista evidencia suficiente:

- Programming Languages
- Databases
- Frameworks & Libraries
- Cloud & Infrastructure
- APIs & Integration
- Development Tools
- DevOps & CI/CD
- Monitoring & Observability
- Methodologies
- Operating Systems
- Other Technologies

No es obligatorio utilizar todas las categorías.

Mostrar únicamente aquellas respaldadas por la KB.

---

# Orden de las categorías

Ordenar las categorías según su relevancia para la vacante.

No utilizar un orden fijo.

---

# Contenido

Cada categoría deberá contener únicamente las tecnologías más relevantes.

No intentar listar absolutamente todo.

---

# Cantidad

Cada categoría debería contener idealmente entre:

3 y 8 elementos.

Evitar listas excesivamente largas.

---

# Formato

Mostrar cada categoría en una única línea.

Ejemplo:

Databases

SQL Server | PostgreSQL | Oracle

Nunca utilizar listas verticales.

Nunca utilizar niveles gráficos.

---

# Priorización

Las tecnologías deberán ordenarse por relevancia para la vacante.

No por orden alfabético.

No por fecha de aprendizaje.

---

# Adaptación

Cada vacante puede generar una versión distinta de esta sección.

Podrán cambiar:

- categorías mostradas;
- tecnologías incluidas;
- orden de aparición.

Nunca modificar hechos.

---

# Niveles

No utilizar niveles subjetivos como:

- Expert
- Advanced
- Intermediate
- Beginner
- ★★★★★

La experiencia ya demuestra el nivel.

---

# Tecnologías repetidas

Evitar repetir tecnologías innecesariamente.

Una tecnología puede aparecer tanto en Experience como en Technical Skills, ya que cumplen funciones distintas.

Sin embargo, no duplicar tecnologías dentro de varias categorías.

Cada tecnología deberá aparecer una única vez en esta sección.

---

# Sinónimos

Utilizar la denominación más ampliamente reconocida por la industria.

Evitar duplicados como:

SQL

SQL Server

Microsoft SQL Server

MSSQL

Seleccionar únicamente la forma más apropiada para la vacante.

---

# Tecnologías relacionadas

No separar tecnologías que normalmente se entienden como una misma competencia.

Ejemplo:

REST APIs

No dividir en:

REST

APIs

---

# Herramientas

Incluir herramientas únicamente cuando formen parte importante de la experiencia profesional.

No agregar herramientas utilizadas únicamente de forma ocasional.

---

# Tecnologías obsoletas

No eliminar tecnologías antiguas únicamente por su antigüedad.

Mantenerlas cuando:

- sean relevantes para la vacante;
- representen una competencia importante del candidato.

---

# Keyword Alignment

Cuando la Job Description utilice una denominación distinta para una tecnología documentada en la KB, utilizar la terminología de la vacante siempre que el significado sea equivalente.

Nunca alterar el significado real de la experiencia.

---

# Consistencia

Mantener el mismo formato en todas las categorías.

No mezclar estilos.

---

# Legibilidad

Toda la sección deberá poder escanearse en menos de 10 segundos.

Eliminar cualquier información que no aporte valor.

---

# Calidad

Antes de finalizar verificar que:

- todas las tecnologías tienen evidencia en la KB;
- no existen duplicados;
- las categorías son relevantes para la vacante;
- no existen niveles subjetivos;
- no existen tecnologías inventadas;
- la sección resume correctamente el perfil técnico.

---

# Responsabilidad

Este documento únicamente define cómo construir la sección **Technical Skills**.

No define:

- estructura general del CV;
- reglas de redacción;
- reglas ATS;
- Professional Summary;
- Professional Experience;
- Selected Projects;
- Education;
- Languages;
- validaciones generales.

Estas reglas se encuentran en los documentos especializados correspondientes.
