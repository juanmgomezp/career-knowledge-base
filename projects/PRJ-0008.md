# Proceso Proactivo de Gestión de Licencias

## Categoría

Proyecto Interno de Support Operations

## Tipo de Proyecto

- Process Improvement
- Service Continuity
- Customer Experience
- Support Operations

---

# Contexto

Durante el análisis periódico de las solicitudes atendidas por mi equipo de Soporte identifiqué que entre un 5% y un 10% de los tickets mensuales correspondían a clientes que habían perdido acceso al sistema debido al vencimiento de sus licencias.

Aunque la reactivación de las licencias no representaba una tarea técnicamente compleja, el proceso era completamente reactivo: el cliente debía detectar el problema, contactar al área de Soporte y esperar la validación del Key Account Manager (KAM) antes de restaurar temporalmente el acceso.

Esta situación generaba interrupciones innecesarias del servicio, afectaba la experiencia del cliente y añadía carga operativa al equipo de Soporte.

---

# Problema

El proceso presentaba varias limitaciones:

- Dependía completamente de que el cliente reportara la pérdida de acceso.
- Requería la disponibilidad del KAM para autorizar reactivaciones temporales.
- Incrementaba el volumen mensual de tickets por una causa completamente predecible.
- Podía afectar la continuidad operativa de clientes con procesos críticos.
- Consumía tiempo del equipo de Soporte en solicitudes que podían prevenirse.

---

# Objetivo

Transformar un proceso reactivo en un proceso preventivo mediante la identificación anticipada de licencias próximas a vencer, permitiendo coordinar las renovaciones antes de que el cliente perdiera acceso al sistema.

---

# Solución

## Detección anticipada

Diseñé una estrategia para identificar semanalmente las licencias próximas a vencer utilizando información del servidor central de licencias.

Se definió una ventana de análisis de 30 días para detectar tanto licencias vencidas como próximas a expirar.

---

## Consulta SQL

Desarrollé un procedimiento almacenado en SQL Server que:

- Obtiene las licencias próximas a vencer.
- Relaciona cada licencia con su cliente correspondiente.
- Filtra únicamente los clientes asignados a mi equipo.
- Ordena los resultados priorizando las licencias vencidas o con expiración más cercana.

La información se exporta posteriormente a Microsoft Excel para facilitar su revisión.

---

## Colaboración con el KAM

Cada semana el reporte es compartido con el Key Account Manager, quien valida las renovaciones en proceso e identifica aquellas licencias que requieren una extensión temporal mientras concluye el proceso administrativo.

---

## Renovación temporal

Una vez aprobadas las licencias, desarrollé un procedimiento almacenado adicional encargado de:

- Reactivar la licencia.
- Actualizar su fecha de vigencia temporal.
- Actualizar automáticamente la vigencia de todos los productos asociados.

Este proceso permitió realizar la reactivación de forma rápida y consistente.

# Evolución Propuesta

Actualmente el proceso requiere intervención manual para generar el reporte, compartirlo con el KAM y ejecutar la actualización de las licencias aprobadas.

Como evolución natural del proyecto, propuse automatizar completamente este flujo mediante una aplicación interna o una API REST que permita:

- Generar automáticamente el reporte semanal.
- Enviar notificaciones al KAM.
- Ejecutar las renovaciones aprobadas.
- Centralizar el seguimiento de las extensiones temporales.
- Escalar la solución para todos los clientes de la organización.

La implementación de esta evolución dependerá de la priorización de iniciativas dentro del área de Operaciones.

---

# Resultados

La implementación del proceso permitió:

- Reducir aproximadamente un **60%** las solicitudes relacionadas con vencimiento de licencias.
- Disminuir interrupciones del servicio ocasionadas por licencias expiradas.
- Mejorar la experiencia del cliente al anticipar posibles afectaciones.
- Reducir la carga operativa del equipo de Soporte.
- Fortalecer la colaboración entre las áreas de Soporte y Comercial.
